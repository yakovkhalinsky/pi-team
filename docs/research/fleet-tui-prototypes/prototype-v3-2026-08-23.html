How to read this prototype

  
    
    
  • Left panel: the Fleet Dashboard view, rendered from buildFleetDashboardLines(snapshot, width) in tools/render-fleet-dashboard-prototype.mjs. The function reads only what buildTeamSnapshot already exposes; columns the snapshot cannot fill are written as the literal marker [tracked-not-yet] so the gap is visible at a glance.
    • 
    
  • Right panel: the existing compact widget, rendered from buildWidgetLines(snapshot) in packages/pi-agents-team/dist/extensions/pi-agent-team/index.js line 387. Same snapshot input as the left panel. Use the right panel as the baseline to see what the Fleet Dashboard adds (and what it costs in lines).
    • 
    
  • Use the width picker (#w=80 / #w=100 / #w=120) and the snapshot picker (#s=idle / #s=one-running / #s=busy) — both are reflected in the URL hash so a link is shareable.
    • 
    
  • The grid is inlined from tools/fleet-dashboard.json — no fetch, no CORS. Update via node tools/render-fleet-dashboard-prototype.mjs.
    • 
    
  • The stubs are the entire point of this prototype. They make the missing data plumbing visible. A future v4 that lands the missing data plumbing can swap the markers for real values without changing the layout.
